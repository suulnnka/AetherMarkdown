# Markdown 语法规范

本规范定义 AetherMarkdown 的语法：**行块模型**（D34）——**每一行独立成块，行与行互不影响**。每行只应用一个主语法（`#` 标题 / `-`、`1.` 列表 / `>` 引用 / `---` 分割线 / 围栏代码块），行内语法（粗体、链接等）正常解析；空行是真实的空块。回车即换行（每行一块）。**凡本文未列出的语法一律不支持**，按普通文字行处理（安全降级，不报错）。

## 支持总表

| 类别 | 语法 | 支持 |
|---|---|---|
| 块级 | ATX 标题 `#`~`######` | ✅ |
| 块级 | 文字行（每行独立成块） | ✅ |
| 块级 | 无序列表 `-` `*` `+`，任意嵌套 | ✅ |
| 块级 | 有序列表 `1.` `1)`，任意嵌套 | ✅ |
| 块级 | 任务列表 `- [ ]` / `- [x]`（仅无序列表） | ✅（复选框纯展示） |
| 块级 | 引用 `>`，嵌套，惰性续行 | ✅ |
| 块级 | 围栏代码块 ``` ``` ``` / `~~~`，info string | ✅（无高亮） |
| 块级 | 简单表格 `| A | B |`（无表头区分，单元格仅行内样式） | ✅（D35） |
| 块级 | 分割线 `---` / `***` / `___` | ✅ |

## 块级语法规则

### 标题

- 仅 ATX 形式：行首 1–6 个 `#` 后必须跟空格或行尾；`#` 后的内容即标题文本。
- `#` 单独成行（或其后仅空白）是**空标题行**：渲染为保持行高的空行（不塌陷为 0 高）。`#` 后无空格直接跟文字（如 `#文`）**不是标题**，按普通文字行处理（CommonMark 规则）。
- **不支持** Setext 形式（`===`/`---` 下划线标题）。`---` 紧跟段落时按分割线处理（见"已知歧义"）。
- **不支持** ATX 尾部关闭序列：`# 标题 #` 中结尾的 `#` 视为标题文本的一部分（偏离 CommonMark，简化心智）。

### 段落与换行（D34 行块模型）

- **每一行独立成块**：回车即分行，行与行互不影响；不存在"段落内多行"的概念（无跨行合并）。
- 空行是真实的空块（可点击输入），连续多个空行各自成块。
- **硬换行**：行尾两个及以上空格，使**下一行**渲染为短间距（`md-gap-short` 类，额外间距 `--md-br-hard-gap`，默认 0——与自动折行的行距完全一致）。编辑器内 `Shift+Enter` 生成规范形式"两空格 + 换行"（D33）。
- 行尾 `\` 无硬换行语义，按字面显示（行内解析器输入恒为单行，D36）。

### 列表（行级生效）

- 无序标记：`-`、`*`、`+`，后跟至少一个空格；有序标记：`数字` + `.` 或 `)`。渲染时无序显示圆点，有序显示**该行自身的标记文本**（`3.` 起始就显示 3，编号不联动、不重新编号——D34）。
- **列表行仅占一行**：下一行无论是什么（普通文字、缩进内容）都是独立行块，不属该项。带标记的行可在视觉上形成嵌套层次（见下），但数据上仍是独立行。
- **嵌套 = 缩进表达**：每 2 个前导空格一级（渲染时左边距递增）；`Tab` / `Shift+Tab` 对列表行整行缩进 ±2 空格。
- 任务列表：无序列表项标记后为 ` [ ] ` 或 ` [x] `（大小写均可），渲染为禁用的复选框 + 文本。有序列表不支持任务语法（`1. [x]` 按普通文本处理）。
- 无"松散/紧凑"区分：相邻列表行间距统一（`--md-item-gap`）。

### 引用（行级生效）

- 行首 `>`（后跟空格可省略）；`>>` 嵌套（每层一条竖线，正文随层数右移）。
- **无惰性续行**：省略 `>` 的行不属该引用；多行引用需每行自带 `>`。相邻引用行间距归零，竖线视觉连续。
- 引用行内容**仅行内语法**（粗体/链接等）；行内的 `- `、`#` 等块级标记按字面文本处理。

### 围栏代码块

- ``` ``` ``` 或 `~~~` 开栏，长度 ≥3，闭栏同字符、长度 ≥ 开栏。
- 开栏后同行内容为 info string（如 ```js）。info 仅作语言标签展示（代码块右上角小字），不做高亮。
- 栏内一切内容按字面处理，不解析任何 Markdown。
- **不支持**缩进代码块（4 空格）：易与列表嵌套内容混淆且现实中多为误触。缩进 4 空格的行按普通段落处理（偏离 CommonMark，见下）。

### 分割线

- 三个及以上连续的 `-`、`*` 或 `_`（不允许混用字符），行内除空格外无其他内容。

### 表格（简单表格，D35）

- 一行以 `|` 分割单元格：`| A | B |`。首尾 pipe 之外仅允许空白；至少 2 个未转义 `|`（至少一个单元格）才算表格行。
- **连续的表格行合并为一个表格**（跨行结构，同代码块），遇非表格行（空行、文字等）结束。
- **不区分表头**：所有内容行同等渲染，无 thead/加粗首行。GFM 分隔行（所有单元格均为 `---` / `:--` / `--:` / `:-:` 形态）不产出内容行，仅作兼容保留在源码中。
- **单元格内仅行内样式**（粗体/行内代码/链接等，走行内解析）；不支持单元格内嵌套块级语法（标题、列表等标记按字面文本处理）——"嵌套尽量避免"。
- `\|` 转义为字面竖线，不分割单元格。
- 编辑态：整个表格作为一个编辑单元显示源码（pipe 与边界空白弱化，单元格内容保持行内排版）；Enter 一律插入换行。

## 行内语法规则

优先级从高到低：行内代码 > 图片 > 链接 > 粗体/斜体/删除线 > 自动链接。

### 行内代码

- 反引号配对；双反引号可包裹含单反引号的内容（CommonMark 标准）。
- 首尾各去一个空格的 CommonMark 规则保留（`` ` x ` `` → `x`）。

### 强调（粗体/斜体）与删除线

- `**x**`、`__x__` 粗体；`*x*`、`_x_` 斜体；`~~x~~` 删除线；可一层嵌套（`**bold *em***`）。
- **简化**：不实现 CommonMark 完整的左右 flanking 判定。配对规则为"同标记成对即生效"，已知边界差异列入下方偏离清单（如 `foo_bar_baz` 中 `_` 是否成对）。`_` 词内配对不生效的常用惯例保留：`foo_bar_baz` 不产生斜体；`foo*bar*baz` 产生斜体。

### 链接与图片

- `[text](url)`；`[text](url "title")`（title 单双引号均可）；URL 含空格时用尖括号 `[text](<my url>)`。
- 图片 `![alt](url)`，alt 文本保留（无障碍与加载失败提示）。
- 链接文本内可嵌套行内语法与图片；图片 alt 内不解析任何行内语法。
- **不支持**引用式链接（`[ref]` + `[ref]: url`）：定义与使用分离，与实时渲染模型冲突，列入偏离清单。
- URL 协议白名单见 architecture.md §10。

### 自动链接

- 尖括号形式：`<https://example.com>`、`<mailto:a@b.c>`、`<a@b.c>` → 链接。
- GFM 字面形式（简化）：独立词以 `https://`、`http://`、`www.` 开头即成链接，截止于空白或常见结尾标点（`)` `]` `，` `。` 等）。**不做** GFM 完整的扩展邮箱识别（`a@b.c` 裸词不自动成链）。

### 转义

- `\` 后跟 ASCII 标点字符 → 输出该字符本身，取消其语法意义。
- 其他位置的 `\` 按字面处理。

## 对 CommonMark 的有意偏离（汇总）

| 偏离 | 决策 | 理由 |
|---|---|---|
| Setext 标题 | 不支持 | 与分割线歧义，实时渲染下体验差 |
| ATX 尾部关闭 `#` | 不支持 | 极少使用，简化 |
| 缩进代码块（4 空格） | 不支持 | 与列表嵌套混淆，多为误触 |
| 嵌套强调的完整 flanking 规则 | 简化配对 | 边界用例收益低；常用场景行为一致 |
| 列表容器 / 编号联动 | 不存在（D34） | 行独立成块：插入文字行不"拆分"列表，编号随行自身标记 |
| 引用式链接 | 不支持 | 定义分离与实时渲染模型冲突 |
| 惰性续行（引用续行省略 `>`） | 不支持（D32） | 行级生效：标记仅对本行有效 |
| 列表项跨行（缩进续行/项内多段） | 不支持（D32） | 行级生效：普通文字行不续入列表项 |
| HTML 直写 | 不支持，按字面文本显示 | XSS 风险与渲染复杂度 |
| HTML 实体（`&amp;` 等） | 不解码，按字面文本 | 简化 |
| 表格 | 简化支持（D35）：仅边缘 pipe 形态、无表头区分、无列对齐/列宽语法、单元格仅行内样式 | 复杂表格编辑交互成本过高，简单形态覆盖绝大多数需求 |
| 脚注 / 定义列表 | 不支持 | D8 |
| GFM 扩展自动链接（邮箱等） | 简化 | 见自动链接节 |
| 软换行 / 硬换行语义 | 每行独立成块（D34）：换行即分行；硬换行（行尾两空格）仅缩短下一行间距 | 行块模型；所见即所得 |
| 行尾 `\` 硬换行 | 不支持，按字面 | 行内解析输入恒为单行（D36） |

**已知歧义处理**：段落行紧跟 `---` 时，`---` 按分割线（因 Setext 不存在，无歧义）；列表项内 4 空格缩进行属于列表项内容（因缩进代码块不存在，无歧义）——两处偏离反而消除了 CommonMark 最著名的两个坑。

## 序列化 / 规范化

数据层保证"未编辑区域逐字节保留"。编辑器**不代写语法**（无自动续行、无自动转换），自身新产生的内容只有三种规范形式：

| 场景 | 编辑器产出的形式 |
|---|---|
| `Shift+Enter` | 行尾两空格 + 换行（硬换行规范形式，D33） |
| `Tab` / `Shift+Tab`（列表行） | 整行缩进 ±2 空格 |
| `Tab`（代码块内） | 插入两空格 |

其余一切标记（`- `、`1. `、`> `、`# `、围栏、表格行等）由用户手写，原样保留、不强改；从磁盘/宿主载入的文档即使含非规范形式也原样展示。
