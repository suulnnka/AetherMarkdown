# 决策记录

本文档记录项目所有已锁定的范围与技术决策，及各自的理由。后续开发以此为准；如需变更，先改这里。

## 一、产品形态

| # | 决策 | 理由 |
|---|---|---|
| D1 | 单栏块级实时渲染（Typora 式），光标所在块显示源码 | 产品定位即此类编辑器 |
| D2 | 不做分栏预览，不做源码模式切换 | 编辑面只保留一种形态，降低维护面 |
| D3 | 零运行时依赖，自研解析器与编辑层 | 项目核心约束 |
| D4 | 以 Markdown 源文本为唯一数据事实，不维护富文本 AST | 天然可逆、undo/序列化简单、嵌入友好 |
| D5 | 只支持桌面浏览器 | 移动端软键盘/触摸是独立的难点矩阵，明确不承诺 |

## 二、语法范围

| # | 决策 | 理由 |
|---|---|---|
| D6 | 支持：标题/段落/粗体/斜体/删除线/行内代码/链接/自动链接/图片/有序无序列表（嵌套）/任务列表/引用/围栏代码块/分割线/转义/硬换行 | 覆盖日常写作绝大部分场景 |
| D7 | ~~不支持表格~~ **修订（D35）**：支持简单表格 | 完整表格编辑交互（单元格光标、行列增删）成本过高，简单形态已够用 |
| D8 | 不支持数学公式、mermaid、脚注、定义列表、HTML 直写、缩进代码块 | 外部依赖、性价比低或安全风险；详见 markdown-syntax.md 偏离清单 |
| D9 | 不做代码语法高亮 | 零依赖下需自写各语言 tokenizer；渲染层预留 class 钩子，未来可加 |

## 三、编辑交互

| # | 决策 | 理由 |
|---|---|---|
| D10 | 不做键盘格式快捷键（Ctrl+B/I/K） | 明确排除 |
| D11 | 图片只认 URL，不做上传/粘贴/拖拽回调 | 缩小边界；网络与存储是宿主的事 |
| D12 | ~~图片点击放大查看要做（内置浮层）~~ **修订**：点击放大交由宿主处理——库发出 `imageClick` 事件（图片 src），不内置浮层；无监听时点击回落为激活该块 | 用户要求；展示类 UI 不是核心库职责，宿主可有自己的查看器/灯箱 |
| D13 | 任务列表复选框纯展示，不可点击 | 明确排除；切换靠编辑源码 |
| D14 | 链接点击 = 在浏览器新标签打开（编辑态与只读态一致） | 用户决定。编辑链接文本靠键盘导航（方向键）或点击链接前后文字进入 |
| D15 | 撤销/重做自建栈，块级粒度 | 浏览器原生 undo 在程序化 DOM 变更后不可靠；块级粒度是明确要求 |
| D16 | 不做符号自动配对 | 与 IME 有冲突风险，收益低 |
| D17 | 粘贴一律清理为纯文本（取 `text/plain`，HTML 丢弃） | 不做 HTML→Markdown 智能转换 |
| D18 | 不做智能粘贴、字数统计、查找替换、大纲/TOC、打字机/焦点模式、导出 HTML | 明确排除 |
| D19 | 只读模式要做 | 渲染逻辑复用，嵌入场景常用 |

## 四、工程与分发

| # | 决策 | 理由 |
|---|---|---|
| D20 | 组件形态：class API（`new MarkdownEditor({ target, ... })`），不注册 Custom Element | "完全无入侵"：Custom Element 需占用全局标签名注册表，有冲突与污染风险；class 挂载零全局副作用 |
| D21 | 样式完全隔离：全部 UI 位于 Shadow DOM | ~~原方案~~ **修订（M2 实测）**：Shadow DOM 内的 Selection/键盘事件在 WebKit 等引擎不可靠，真实点击与输入完全失效；改为 light DOM + `.aether-host` 强作用域前缀 + 继承属性显式重置，实现等效隔离 |
| D22 | 主题抽象为两套 CSS（light/dark），宿主可改 | 以 CSS 自定义属性实现，穿透 Shadow DOM 边界 |
| D23 | 库不管理高度：根元素不设高度/滚动样式 | 高度是宿主容器（input 外框）的职责，库保持自然文档流 |
| D24 | 分发为普通 ES Module 源码，由宿主的 webpack 等工具直接导入；不做单文件打包产物 | 用户决定；主题 CSS 作为普通 css 文件由宿主 css 管线导入 |
| D25 | 结构样式由 JS 内嵌字符串注入宿主元素 | 避免 `?raw` 等 bundler 专属语法，任何打包器零配置可用（随 D21 修订不再使用 Shadow DOM） |

## 五、开发路径与预算

| # | 决策 | 理由 |
|---|---|---|
| D26 | 不做"分栏编辑器"中间产物；解析器独立先行、测试驱动，之后直接开发实时渲染编辑面 | 分栏 UI 对最终形态无对外价值 |
| D27 | 图片渲染尺寸约束：宽 ≤ 内容列宽、高 ≤ 75vh（`--md-img-max-height` 可调），保持纵横比 | 用户要求"合理大小"，防止大图撑爆排版 |
| D28 | 体积预算：JS gzip ≤ 25 KB（目标 18–22 KB），CSS（Shadow 结构样式 + 两套主题）gzip ≤ 3 KB；超出即审视实现冗余 | 嵌入友好，列入验收 |
| D29 | 项目名 AetherMarkdown，包名 `aether-markdown`，宿主元素 class `aether-host` | 定名 |
| D30 | 编辑态表现参考 milkdown/Typora：保持块级排版（标题字号/粗体等），语法标记（#、**、- 、](url)、围栏）以 `--md-marker` 弱化色显示，无底色；编辑态 DOM 的纯文本与源码形态逐字节一致（extractText ↔ source.slice 可互换，幂等同步的前提） | 用户要求；灰底+纯文本源码态观感差 |
| D31 | 回车统一为插入换行符（软换行渲染 `<br>`，GFM 风格），**不做**回车自动续行列表/引用、不做空项回车退出——结构必须由用户自行书写标记；列表项编辑态显示标记语法（弱化色、可编辑），隐藏渲染标识（CSS 项目符号置 none、复选框不显示），避免语法与圆点重复 | 用户要求；回车行为更可预测、编辑器不代写语法 |
| D32 | 语法定义为**行级生效的非标准 Markdown**：块级标记仅对所在行起效（无惰性续行、普通文字行不续入列表项；带标记的行仍可在项内开子块）；回车即换行（软换行渲染 `<br>`） | 用户定义的产品语义；行级模型更可预测，编辑器行为与语法语义一致 |
| D34 | **行块模型**：每一行独立成块（扁平结构，无容器）——无跨行段落合并、无列表容器（插入文字行不再"拆分"列表、编号随行自身标记）、空行是真实可输入的空块（彻底移除虚拟段机制）、引用行独立渲染（`>>` 深一层）；围栏代码块是唯一跨行结构。Enter=分行、Shift+Enter=短间距行、行首退格=剥标记/并行 | 用户要求"每一行都独立、不要上下干扰"；架构大幅简化（删除虚拟段/物化/容器对齐全部机制） |
| D35 | **简单表格**：仅支持 `| A | B |` 边缘 pipe 形态的连续行（跨行结构之二，同代码块机制：整表一个编辑单元）；不区分表头（GFM 分隔行仅兼容保留、渲染跳过），无列对齐/列宽语法；单元格内仅行内样式，不支持嵌套块级语法；`\|` 转义 | 用户要求"仅支持简单语法、不区分表头、嵌套尽量避免、表格内仅行内样式"；复用代码块的跨行单元机制，编辑面零新增交互 |
| D36 | **删除 HTML 序列化管线与导出中间层**：删除 `parse/html.js`（`markdownToHtml` 等，生产零调用）与 `parse/index.js` barrel、`package.json` 的 `./parse` 子路径；包导出面收敛为 `MarkdownEditor` + `parseLines`/`parseTableRow`/`parseInline`/`plainText`/`sanitizeUrl`；行内解析器移除不可达的换行分支（输入恒为单行）；清理孤儿 CSS 变量与死代码；全部文档按代码现状重写 | D18 已排除"导出 HTML"，编辑器渲染直接构建 DOM（textContent 无注入面），字符串管线是与 dom.js 并行的双维护路径；行块模型简化后死代码与过期文档累积，集中收敛 |
| D37 | **演示页 Vite 打包 + CI 部署 Pages**：`demo/index.html` 为 Vite 入口（devDependencies 仅 vite，运行时零依赖不变），GitHub Actions 跑测试 + 构建 + 部署 Pages；构建产物 dist/ 不入库 | 用户要求；Pages 经 Actions 部署无需手工同步产物，构建时自动产出 min/gzip 体积报告对照 D28 预算 |
| D38 | **分隔符改为可编辑行**：移除 hr 单元的"不可编辑"分支与 `editable` 标志，渲染态仍是 `<hr>`（点击激活该行显示 `---` 源码，光标行尾），上下间距 1em 保持；跨界删除（分隔符行上行首退格/行尾 Delete，或相邻行的行首退格/行尾 Delete）一律删一个标记字符，少于 3 个自动回退普通文字行，行不合并 | 不可编辑单元引发一系列边界 bug（光标丢失、点击抢占、合并意外、末行补行）；可编辑化后与普通行共用全部机制，仅保留点击激活与跨界删字符两个小特例 |
| D39 | **编辑态不对缩进做加工**：移除前导空格的零宽收纳（md-indent）与编辑态 marginLeft，嵌套列表行进入编辑态按源码字面显示前导空格（pre-wrap 占位）；渲染态层级缩进（每 2 空格一级的左边距）不变 | 用户要求：编辑态应忠实呈现源码原貌，不擅自施加额外缩进 |
